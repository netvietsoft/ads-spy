# i18n — Quy ước đa ngôn ngữ cho FE khách (Phase 6)

> **Phase 0 chỉ tài liệu.** Toàn bộ nội dung dưới đây là **quy ước dự kiến** cho **FE khách hàng mới**
> (`dpboss.pet`, tiểu dự án #6 trong [`roadmap.md`](./roadmap.md)) — app này **chưa tồn tại**, sẽ dựng
> ở **Phase 6** sau khi các subsystem #1–5 (User & Auth, Subscription, Payment, Dashboard admin, API
> mobile) hoàn thành. **Không áp dụng** cho `apps/web` hiện tại (Admin FE, xem
> [`frontend.md`](./frontend.md)) — Admin FE chỉ dùng tiếng Việt, không có i18n.

## 1. Cấu trúc thư mục

File dịch đặt tại `src/i18n/` của app FE khách, mỗi ngôn ngữ 1 file JSON, **key lồng theo namespace**
(không dùng key phẳng kiểu `"nav.home"` làm chuỗi — namespace là object lồng, dễ nhóm theo màn
hình/khu vực và tránh trùng key khi file lớn dần):

```
src/i18n/
├── vi.json   # ngôn ngữ mặc định / fallback
└── en.json
```

Ví dụ `src/i18n/vi.json`:

```json
{
  "nav": {
    "home": "Trang chủ",
    "shops": "Shop",
    "products": "Sản phẩm",
    "reports": "Báo cáo"
  },
  "auth": {
    "login": "Đăng nhập",
    "logout": "Đăng xuất",
    "email": "Email",
    "password": "Mật khẩu"
  },
  "common": {
    "save": "Lưu",
    "cancel": "Hủy",
    "loading": "Đang tải..."
  }
}
```

Ví dụ `src/i18n/en.json` (cùng cấu trúc key, khác giá trị):

```json
{
  "nav": {
    "home": "Home",
    "shops": "Shops",
    "products": "Products",
    "reports": "Reports"
  },
  "auth": {
    "login": "Login",
    "logout": "Logout",
    "email": "Email",
    "password": "Password"
  },
  "common": {
    "save": "Save",
    "cancel": "Cancel",
    "loading": "Loading..."
  }
}
```

Quy ước đặt tên key: `<namespace>.<key>`, namespace theo khu vực UI (`nav`, `auth`, `common`,
`shop`, `product`, `report`…), key trong namespace đặt theo `camelCase`, ngắn gọn, mô tả đúng nội dung
chuỗi (không đặt theo vị trí trên màn hình).

## 2. Ngôn ngữ hỗ trợ + fallback

- Danh sách ngôn ngữ hỗ trợ khai ở 1 hằng số dùng chung, ví dụ `SUPPORTED_LANGS = ['vi', 'en']`.
- **Fallback mặc định: `vi`** — nếu không xác định được lựa chọn của người dùng (chưa từng chọn, giá
  trị lưu không hợp lệ, hoặc ngôn ngữ trong cookie/localStorage không nằm trong `SUPPORTED_LANGS`) thì
  dùng `vi`.
- Nếu 1 key tồn tại ở `vi.json` nhưng thiếu ở ngôn ngữ khác (ví dụ quên dịch key mới sang `en.json`) —
  hiển thị lại giá trị từ `vi.json` cho key đó (fallback theo từng key, không fallback cả trang) và
  log cảnh báo ở môi trường dev để dev biết còn thiếu bản dịch.

## 3. Provider chọn ngôn ngữ

Một `LanguageProvider` (React Context) bọc toàn app, chịu trách nhiệm:

- Đọc lựa chọn ngôn ngữ hiện tại theo thứ tự ưu tiên: cookie `lang` (đọc được cả ở server, tránh
  "flash" sai ngôn ngữ khi SSR/hydrate) → nếu không có, đọc `localStorage['lang']` (client) → nếu vẫn
  không có hoặc giá trị không hợp lệ, dùng fallback `vi` (mục 2).
- Khi người dùng đổi ngôn ngữ: ghi đồng thời `localStorage['lang']` và cookie `lang` (để lần load
  trang sau, kể cả server-side, lấy đúng ngôn ngữ đã chọn), rồi re-render toàn app với bộ key mới.
- Expose ra ngoài qua 1 hook, ví dụ `useTranslation()`, trả về:
  - `t(key: string) => string` — tra key theo namespace lồng (`t('nav.home')` → đọc
    `dict.nav.home`).
  - `lang` — mã ngôn ngữ hiện tại (`'vi' | 'en'`).
  - `setLang(lang) => void` — đổi ngôn ngữ.

Phác thảo (minh họa quy ước, KHÔNG phải code thật — chưa có file này trong repo):

```tsx
// src/i18n/LanguageProvider.tsx (dự kiến, Phase 6)
const SUPPORTED_LANGS = ['vi', 'en'] as const;
const FALLBACK_LANG = 'vi';

function resolveInitialLang(cookieLang?: string, storedLang?: string) {
  const candidate = cookieLang ?? storedLang;
  return SUPPORTED_LANGS.includes(candidate as any) ? candidate : FALLBACK_LANG;
}
```

## 4. Cách dùng trong component

```tsx
import { useTranslation } from '@/i18n/LanguageProvider';

function HomeHeader() {
  const { t, lang, setLang } = useTranslation();
  return (
    <header>
      <h1>{t('nav.home')}</h1>
      <button onClick={() => setLang(lang === 'vi' ? 'en' : 'vi')}>
        {lang === 'vi' ? 'EN' : 'VI'}
      </button>
    </header>
  );
}
```

Không hard-code chuỗi hiển thị cho người dùng trực tiếp trong JSX — luôn qua `t('namespace.key')`, kể
cả label ngắn (nút, placeholder, thông báo lỗi).

## 5. Cách thêm 1 ngôn ngữ mới

1. Tạo file mới `src/i18n/<mã-ngôn-ngữ>.json` (ví dụ `ja.json`), copy nguyên cấu trúc namespace/key từ
   `vi.json`, dịch toàn bộ giá trị.
2. Thêm mã ngôn ngữ vào `SUPPORTED_LANGS`.
3. Thêm lựa chọn ngôn ngữ mới vào UI chuyển ngôn ngữ (component chọn ngôn ngữ dùng chung, ví dụ trong
   header).
4. Không cần sửa `LanguageProvider` hay bất kỳ component nào đang gọi `t()` — chúng chỉ phụ thuộc vào
   key, không phụ thuộc vào số lượng ngôn ngữ.

## 6. Cách thêm 1 key mới

1. Thêm key vào `vi.json` trước (bắt buộc — `vi` là ngôn ngữ fallback, thiếu ở đây sẽ hiển thị lỗi/rỗng
   thay vì fallback được).
2. Thêm cùng đường dẫn key đó (namespace + tên key giống hệt) vào tất cả file ngôn ngữ khác đang hỗ trợ
   (`en.json`…). Nếu tạm thời quên, ứng dụng vẫn chạy được nhờ cơ chế fallback theo key ở mục 2, nhưng
   cần dịch bổ sung sớm.
3. Dùng key mới trong component qua `t('namespace.keyMoi')`.
