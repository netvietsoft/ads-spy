- **2026-08-07 — Đổi domain production sang `mmo-coin.com`, lộ ra 8 vấn đề riêng biệt:** cookie `Domain` sai làm login loop im lặng (login 201 nhưng `/me` 401); đích API bị Next **nướng lúc build** nên restart không ăn; nginx thiếu server block; mật khẩu MySQL lệch sau khi chuyển DB sang ổ mới (user/quyền đủ, dữ liệu còn nguyên 48.835 shop). Chi tiết + task còn lại: [`handoff-2026-08-07-doi-domain.md`](handoff-2026-08-07-doi-domain.md).
- **2026-08-07 — Ba regression của chính bản "tối ưu" hôm 06/08, cùng một kiểu sai:** (1) nạp sẵn `COUNT(*)` lúc boot — đo local 5,3M dòng rồi suy ra prod, mà prod có **18,17M dòng** nên câu đó *không bao giờ xong*; `kill` client KHÔNG huỷ truy vấn trong MySQL nên mỗi restart chồng thêm 1 zombie → **7 câu treo 1,6-2,4 giờ**, bỏ đói cả DB. (2) thêm cột **không index** vào `ORDER BY` → mất index, chuyển sang filesort đọc cả LONGTEXT 1GB → **124s/lượt job** (`EXPLAIN` hiện ngay chữ `Using filesort`; sửa xong 37ms → **2ms**). (3) chuyển API sang same-origin mà không soi lại block nginx đích → thiếu `proxy_read_timeout 180s`. Bài học chung: **đổi một mắt xích thì phải kiểm mắt xích kế tiếp**.
- **2026-08-07 — `COUNT(*)` không lọc trên bảng lớn là không khả thi:** đổi sang số ước lượng InnoDB (~2ms, lệch 10-15%) cho count không-lọc, giữ `COUNT(*)` thật khi **có** lọc (bám index: 28-184ms), và mọi COUNT kèm `MAX_EXECUTION_TIME` để MySQL tự huỷ câu bất thường — zombie không thể sống sót qua restart nữa.
- **2026-08-07 — AITDK `err:1005` cho mọi request = key/tài khoản, không sửa được bằng code:** đã loại trừ domain, endpoint, code app, key sai, signature/version, Cloudflare — bằng đối chứng `gptzero.me`, domain mà đúng key này lấy được dữ liệu thật ngày 29/07.
